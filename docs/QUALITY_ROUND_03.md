# Quality Round 03 — 全量待审形态与补充正文失效检查

状态：本轮全量静态复核与验证完成；全库质量缺口尚未全部关闭。范围仍是本地 PDF 对应的 224 个 general SQL 包；不连接数据库、不提交推送。

基线：Quality Round 02 的 523 个 manifest、3818 条用例、126 条有限写入形态待审记录。

## 顺序与验收

1. 补充正文失效：验证快照纳入 source ledger 声明的 supplemental body，覆盖直接包、传递消费者及无关包隔离；修改正文不必等待 inventory。旧快照缺失这类证据不能宣称 fresh。
2. 按根因处理全部 126 条记录：仅扩展可证明的有限列数、列名、类型检查。递归 CTE、多表写入、视图可更新性、默认值执行效果等不能以猜测关闭。
3. 对全部 224 包、523 个 manifest 重新生成/审计；输出每条旧待审记录的新状态与仍需的证据，不只汇报通过率。
4. 全量回归与真实跨章临时副本失效探针通过后，记录最终结果。剩余人工/数据库/模型扩展任务保留明确阻塞，不缩小分母。

`checked` 仅表示检查器列出的有限写入形态成立，不表示整条 SQL 正确或已经执行。文件结构、事实分母、Pairwise 覆盖要求、目标错误 Oracle 门禁均不降低。

## 已实现的两批修正

### 补充正文持续失效检查

内部 queue 快照新增 `supplemental_sources` 证据，不修改 V1 factor/source 的公共字段。
直接包及传递依赖都记录补充正文路径与 SHA-256；每次 freshness 重读实际文件。
正文改变、删除、catalog/ledger 不一致、越出语料目录或 URL 缺少本地证明，均不能保持 fresh。
无补充来源的旧快照仍兼容；有补充来源但缺证据的旧快照必须重新验证。

验证结束时若依赖输入无法快照，任务返回 `needs_review` 并保留 `input_snapshot` 错误，
不会崩溃后遗留旧的 `static_complete`。这仍是章节/包级失效，不是逐 Fact 最小失效；
补充正文引用也不被强行当作有向无环的包抽取依赖（正文引用可能相互引用）。

跨章探针配置独立列出 8 种补充正文的实际消费者，而非根据本次 freshness 输出反推
“预期答案”。主正文变化除影响包 DAG 下游外，也应影响直接引用该正文的包及其下游。

### 有限 SQL 形态检查

- 修复缩进 CREATE TABLE 在规范化前后使用不同字符偏移的问题。
- INSERT 的已知目标别名参与列名匹配；SELECT 输入的 WHERE/RETURNING/冲突尾部不再妨碍投影列数检查。
- 非递归、只读 SELECT CTE：逐个解析输出列和类型，支持有限显式列名和前序已定义 CTE 引用。
  递归、数据修改 CTE、未命名表达式、未知查询、重名及未解析前向引用保留待审；CTE 不能冒充可写 fixture。
- UPDATE FROM 仅在来源为已知单表且 RHS 为字面量时检查赋值形态；涉及来源名称解析仍待审。
- UPDATE 的继承标记与多目标有限赋值：只处理已知表、显式不同别名、限定目标列及字面量。
  不证明继承行集、跨表求值顺序、WHERE 或 FROM 行为。
- INSERT ALL/FIRST/WHEN 的有限分支逐一检查目标列与实际查询输出；不证明条件选择顺序或运行时写入结果。

本轮不靠增加 SQL 数量体现进展：全部 case 身份、预期和规模保持不变。
126 条旧待审记录中，48 条新增有限形态证据（INSERT 21、UPDATE 19、INSERT ALL 8），78 条仍待审。
全部 202 条适用写入候选为 124 checked、78 needs_review；另 3616 条不属于这个检查器的范围。
其中 checked 含 6 条负向候选：仅列形态吻合，不代表负向目标错误已验证。

## 全量来源与逐 case 对账

`scripts/reconcile_quality_round.py` 拒绝重复 case ID、旧 case 消失以及因子/清单/预期被替换，
为每条旧待审 case 写入前后状态和下一项所需证据。它不会修改规格或任务状态。

来源核对覆盖全部 224 包：factor、source ledger、catalog、实际章节正文、产品版本和父 PDF 哈希。
119 个包共 195 条补充引用也逐条核对。使用全量 general catalog、第三批补充 catalog、
第五批（PLAN_TABLE）与第九批（PG_RESOURCE_POOL）catalog；原始文件不复制到公开文档中。
多份历史拆章中按精确 document/relpath/hash 选择匹配正文，报告保存所用路径，不假装只有一个语料目录。

当前全库仍有 2388 条关联待办（不是独立特性分母）：603 条未决事实、869 条 feature 缺口、
244 条 value 缺口、1 条 rule 缺口、98 个目标错误待校准、510 个待执行场景、7 条场景事实缺口、56 包无普通 manifest。
本轮增加检查证据没有关闭这些全域/行为缺口，也没有把它们统称为“环境不支持”。

## 三章不能共用普通事务清理

| 阶段 | 正文依据 | 需要保留的限制 |
| --- | --- | --- |
| CREATE | L8–14 | 管理权限；不允许事务块；不支持两阶段事务；部分步骤失败可能有目录、文件、软链接残留 |
| ALTER | L8–20 | ALTER 权限、OWNER 的额外成员关系；行存表相关操作不允许事务块；不能借同属主无操作成功证明变更权限 |
| DROP | L8–15 | 所有者/DROP 权限；表空间必须无对象；删除不可回滚且不允许事务块；失败后的 IF EXISTS 重试也必须限定同一受控对象 |

因此本组不能采用其他测试的 `BEGIN → CREATE → 目标 → ROLLBACK`。普通空 Schema
也不能证明表空间、其他数据库中的对象或文件系统没有残留。

路径条件来自 CREATE L58–73：相对目录位于各节点数据目录的 `pg_location` 下、
最多两层；绝对路径需本地、不能位于数据库数据目录内、符合字符与权限要求。
PDB 只支持相对路径（L22–23）。绝对路径不存在时可由数据库创建，但这不免除
批准范围、父目录权限、空目录和失败残留的检查。

## 后续生命周期的最小顺序

1. **批准及只读盘点**：验证实例、名称、路径、成员关系；记录创建前目录状态。
   此阶段不预先删除同名对象/目录，不修改全局权限。
2. **创建**：按授权的非事务执行方式执行一条有限 CREATE；分别记录 SQL 结果和
   实际元数据/路径。SQL 失败也不能假定没有文件副作用。
3. **单一 ALTER 子场景**：每次只改一种属性。重命名记录新名字，但不得假定位置
   跟着变化；原文示例保留旧目录。OWNER 路线单独验证，不默认与其他动作混测。
4. **元数据 Oracle**：按本版 `pg_tablespace` 已核对的字段读取名称、属主、选项、
   限额与relative。RESET 后不能硬断言等于测试前显式值；必须区分清除覆盖项与当前默认。
5. **清理**：确认对象仍属于本次创建、无其他数据库对象占用，再按独立批准清理。
   DROP 失败时，本章要求的 IF EXISTS 重试不得扩大到其他名字或反复吞掉错误。
6. **残留核验**：数据库元数据与服务端目录/链接分开核验。仅在事前批准、精确归属
   已证明的路径内安排恢复；无法证明的残留转人工，绝不生成通用 `rm -rf`。

DROP 是不可回滚的删除，不称“恢复”；只允许清理本次专用资产。若无法保证其他
会话不使用该表空间，这个生命周期尚不具备自动执行条件。

## 保留的来源冲突与未覆盖项

- CREATE L8 允许继承内置角色创建，L56–57 又写“只有系统管理员”；现有
  `create_tablespace_fact_privilege_conflict` 保留，不强行选一条覆盖另一条。
- CREATE MAXSIZE 的字面上限与“64位有符号整数”措辞不一致；仍保留原文与
  `create_tablespace_fact_maxsize_conflict`，不自行改成 `2^63−1`。
- CREATE 的 page cost 允许范围包含0，ALTER 的参数说明为正浮点数；不能用一个
  共享区间覆盖两章。relative路径、PDB、HCS建议、文件系统限制也不能合并成笼统“不支持”。
- ALTER 五类动作的正文事实当前多被标为 constraint，尚未完整拆成有来源的语法分支；
  本轮只修必填声明，不声称完成 ALTER 的动作抽取或合法值域。
- 当前缺少服务端盘点、权限校准、所有权记录与实际恢复执行器；因此不新增假 fixture。

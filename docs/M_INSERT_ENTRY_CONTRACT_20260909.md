## 修复的实际缺口

同一张 `t(id INT, qty INT DEFAULT 7)`，`INSERT INTO t VALUES(1,DEFAULT)` 原本可检查，而 `INSERT t VALUES(1,DEFAULT)` 被标为未识别。`INSERT INTO t SET id=1,qty=DEFAULT` 也没有接入共享输入合同。

本地 M INSERT 正文 L19–48 明确列出可选 INTO、VALUE/VALUES 和 SET 产生式；L76–81 说明省略列与输入对应关系，L98–99 说明 DEFAULT。正文哈希与 source.yaml 一致：`8bb5cd8bc169b34969fb1c4940bf113f87ac75e797896a6d7ca157cb8361f0b0`。

本轮按失败回归和最小修改推进，未重新抽取全书、未改变包模型，也未手改生成 SQL。

## 实现边界

- 只有声明为 `m_compat` 的来源范围选择可选 INTO 入口。一般章节不因此接受省略 INTO。
- VALUE 单数形式原本已识别，没有另造实现。
- IGNORE、ALL、FIRST 等分支关键字不被错当作表名；IGNORE 错误降级、hint 和复杂入口保留待审。
- M INSERT SET 是一行新输入，不是 UPDATE 旧行。有限实现接受不重复的简单目标列和字面量/DEFAULT，复用真实 fixture DDL 的默认值、非空、生成列与省略列检查。
- SET 后的简单冲突更新继续调用源行列/DEFAULT 合同；两段分别检查。
- SET 中的跨列引用、自引用、重复赋值顺序、子查询、复杂表达式和行别名不求值；视图 DEFAULT 不从基表血缘推定。
- `conflict_source_scope` 这一既有入口参数现在也用于选择上述有限 M 入口；它是来源选择，不是实测数据库兼容模式。

例如 `INSERT t SET qty=2` 不得因为省略 id 就当作“原 id 不变”：id 是需要为新行填充的字段。已有回归验证普通表缺省 NULL 与 NOT NULL 的矛盾会暴露，而动态 DEFAULT、生成列结果和视图 DEFAULT 仍待审。

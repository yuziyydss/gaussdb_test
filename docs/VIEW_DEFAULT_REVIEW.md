# 视图与派生目标DEFAULT：本轮评审结论

当前写入审计剩余16条needs_review全部属于这一个共享语义缺口：一般INSERT 8条、
M INSERT 4条、一般UPDATE 2条、M UPDATE 2条。它们不是16种独立错误，也不是16条
已证明不支持的SQL，仍保留原正向语法候选和待审状态。

## 原文能证明什么

一般INSERT正文L42–48明确有视图/子查询的DEFAULT VALUES和显式DEFAULT语法；
L230–257说明可插入列的基表血缘，L270–280及L298–299说明一般默认值填充。
一般UPDATE L117–143及L169–172也分别定义可更新列和DEFAULT。
这证明它们值得测试，不足以单独解决视图默认值、基表默认值及缺省NULL的实际应用顺序。

一般ALTER VIEW L19–28有SET/DROP DEFAULT语法，L111–115有示例；但L80–81同时
注明该参数暂无实际意义。不能只选语法/示例推断优先级，也不能只据这句话推断
所有视图DML的DEFAULT都不支持。

M INSERT L39–47有视图VALUES/SET，L76–81和L98–99说明一般默认值；M UPDATE
L148–168和L202–204分别说明可更新列和DEFAULT。M CREATE VIEW的列名、查询和
CHECK OPTION规则同样不是默认值继承规则，不从一般模式借用未经验证的结论。

## 对实际候选的影响

一般模式当前相关基表的id/note没有显式默认值；M模式基表声明id默认7、qty默认9。
血缘检查能定位这些列，仍不能将“基表没有DEFAULT”直接替换为“视图DEFAULT就是NULL”，
也不能把M视图qty默认推成9并标为行为通过。

本轮不再尝试靠文本血缘补丁将这16条改绿。下一步需要更明确的产品说明，或获得授权后，
在各自物理模式和独立新资产中观察原候选的目标结果/原始错误、基表行和必要元数据。
精确Oracle留待校准，不能把任意错误当命中；现有含DROP IF EXISTS/CASCADE的fixture
更不能直接丢到已有业务Schema中试跑。

此结论只涵盖已核七章的指定段落，不声称全书没有其他解释。逐case SQL、前置、模式、
当前报告映射及来源段落hash保存在本轮work审查账本；没有更改因子ready或全覆盖结论。

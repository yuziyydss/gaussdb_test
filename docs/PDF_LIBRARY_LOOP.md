## 范围与停止条件

本轮不是把全书直接转换成224个命令包。书签目录登记、正文抽取、语义建模、静态检查和实机验证必须分开展示。

- 全书线：建立所有书签节点的类型、父子关系、页内边界、正文新鲜度、包绑定与测试资产去向。父节点可能含独立正文，不能简单删掉；父子范围不能相加为页数覆盖率。
- 基础线：只处理 `docs/data/pdf_foundation_pilot.json` 的六个通用主题：1.3.1、1.3.3、1.3.4、1.5、1.7.1、1.9.4。必要外章登记依赖，不默默扩大本轮分母或混入M兼容规则。

当六主题均有逐条来源处置/未决项、来源审计通过且待接入缺口明确时，保存来源阶段报告；这不是语义、生成或实机闭环。按用户最新抽取优先指示，可继续登记并推进下一批通用数据类型正文，正式接入留待集中处理。如果必须扩大公共Schema语义，先形成小范围版本化设计，不擅自把非命令内容伪装为SQL命令包；只把相关接入项暂缓，不阻止独立正文抽取。全部已授权来源工作结束、用户叫停或确需新权限且没有独立安全事项时暂停loop并汇报。

## 每轮工作步骤

1. 读取最新用户指示、本文件和 `work/pdf_foundations_2026_09_07/checkpoint.md`。先确认是否有仍在运行的测试/抽取，不能重复启动或并发改同一文件。
2. 选一个有证据的增量：原子事实抽取、来源复核、共享契约评审，或者一个消费者缺陷。不能连续只重写总结而没有新增证据/修复。
3. 原文按catalog边界裁切，必要时渲染PDF表格核对。AI解释和程序抽取分开；不得用搜索到的其他版本或模型记忆补写产品结论。
4. 每条事实记录章节哈希、行号和事实类型；未处理正文保留unmapped，不用超长unit声称原子覆盖。基础草案先保存在本轮工作目录，不被正式生成器自动加载。
5. 依赖分两种：planned仅表示待评审关系；真正注册的Fact/Fixture引用必须通过存在性、导出、类型和DAG检查。报告不能把planned冒称已消费。
6. 改契约前写失败测试；改后运行定向回归，涉及公共代码再运行完整静态回归。测试期间冻结受测文件，保存命令、退出码及输入指纹。原有case ID/SQL/预期变化必须解释，不删用例或缩域换通过率。
7. 以新目录保存本轮输出，更新检查点：实际产物、证据、验证结果、未解决项、下一具体动作、活跃进程ID。每轮末必须有可接续状态。

## 当前工具与产物

- `scripts/extract_pdf_sections.py`：复用精确书签拆章器，首批正文放在独立corpus，不覆盖现有主catalog。
- `scripts/build_pdf_book_ledger.py`：合并同一PDF及outline的正文证据；检查父PDF、章节哈希和消费者存在性；只写新的work报告目录。
- `tests/test_pdf_book_ledger.py`：分类、父子节点、重复路径、模式隔离和禁止虚假状态提升。
- `docs/data/pdf_foundation_pilot.json`：首批六主题及planned消费者，不是生产Fact引用。
- `docs/data/pdf_foundation_claims_draft.json`：部分原子主张草案，复用现有Fact字段但不进入正式注册表；未读正文不会隐去。
- `scripts/audit_foundation_draft.py`：检查草案章节哈希、行锚点、引用片段，显式输出unmapped行；这种检查不能证明语义正确或原子性完整。

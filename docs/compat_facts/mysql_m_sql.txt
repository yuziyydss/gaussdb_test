              GaussDB数据库中的标识符存在以下差异：

              ●   GaussDB无引号标识符中不支持以美元符号（$）开头，MySQL无引号标识符中

              ●   GaussDB标识符支持U+0080~U+00FF扩展字符，MySQL标识符支持U+0080~U

4.4.2.8 驱动
              ●   GaussDB中，驱动PBE接口通过文本模式传参时，如果GUC参数
                  m_format_behavior_compat_options中不包含disable_zero_chars_conversion选
                  项时，服务端会将参数中的“\0”字符替换为空格，与MySQL行为存在差异。
              ●   如果GUC参数m_format_behavior_compat_options中包含
                  disable_zero_chars_conversion选项，服务端将禁止“\0”字符转换为空格，与
                  MySQL行为一致。
              ●   使用MySQL JDBC驱动连接数据库时，当调用setAutoCommit(false)后，若事务
                  中的任一SQL语句执行失败，该事务将进入中止状态。此时须先显式调用
                  rollback()以终止当前事务，才能使连接恢复到可正常使用的状态。但当使用
                  MySQL JDBC驱动连接MySQL数据库时，事务中某条语句失败后，默认只回滚该
                  失败语句，事务仍处于活动状态，可以继续执行其他语句，无需立即回滚。
              ●   当通过JDBC PreparedStatement对象的setBigDecimal或setObject接口绑定
                  NUMERIC类型参数，与整型、时间类型进行加法、减法、乘法或取模运算时，结
                  果的精度为NUMERIC的最大精度，此行为与MySQL-8.0一致，而与MySQL-5.7不
                  一致。
              ●   当通过JDBC PreparedStatement对象的setTime或setTimestamp接口绑定参数，
                  且url参数中开启mCompatibleSetDateTime=true时，默认带6位毫秒，归类为
                  NUMERIC类型参数，此行为与MySQL-8.0一致。
              ●   GaussDB JDBC的PreparedStatement对象的setTime接口会保留毫秒数值，而
                  MySQL JDBC则会丢弃毫秒数值。
